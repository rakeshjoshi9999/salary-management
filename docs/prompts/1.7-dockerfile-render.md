## Outcome

Multi-stage Dockerfile with Spring Boot layered-jar extraction, and `render.yaml`
declaring the whole service — docker runtime, `rootDir`, Singapore, free plan, health
check path, and four environment variables as `sync: false` so Render prompts for the
values and no credential enters the repository.

Claude built and ran the image locally before handing it over: it serves health as UP
and creates Flyway's history table in a real Postgres 18.6 from inside the container.

**The first deploy failed because of Claude's own placeholder convention.** The runbook
wrote the template as `<SM_PGHOST>`, and the angle brackets were pasted into `DB_URL`
along with the value, producing `UnknownHostException` on a bracketed hostname. Angle
brackets are the one placeholder style that looks like punctuation and survives a
copy-paste. The guide now uses bare words.

That failure was still informative: it proved the image built and ran on Render, that all
three variables bound, and that the app refused to start rather than coming up and
serving a health check that lied — which is what putting Flyway in the boot path buys.

Claude also overstated the image size beforehand, estimating ~180 MB against an actual
392 MB, having guessed instead of measuring.
