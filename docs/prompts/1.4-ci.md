# 1.4 — GitHub Actions CI

**Task:** `TASKS.md` 1.4 · **Date:** 2026-10-23 · **Tool:** Claude Code

## Prompt as given

> commit the tests and continue with CI

## Outcome

A workflow running the backend suite on every push, on `ubuntu-latest` with Temurin 21
and a cached Maven repository. Testcontainers needs no setup step because the runner
already has a working Docker daemon. Surefire reports upload even on failure.

Two findings worth keeping:

- **A real bug caught before it fired.** `backend/mvnw` was committed as mode `100644`
  because Git on Windows sets `core.fileMode=false`. On a Linux runner `./mvnw` would
  have failed with permission denied. Fixed with `git update-index --chmod=+x`.

- **Claude got the action versions wrong twice.** It first reached for `@v4` reasoning
  that older majors were the conservative choice; the runner reported all three as
  deprecated. It then guessed `@v5`, still stale for `upload-artifact`. Only after
  querying the GitHub API did it find the actual latest — checkout v7, setup-java v6,
  upload-artifact v7. Two wasted round trips from assuming rather than checking, and a
  reminder that "conservative version" reasoning does not survive a knowledge cutoff.
