# 8.8 — UI redesign, foundation

**Task:** `TASKS.md` 8.8 · **Date:** 2026-11-13 · **Tool:** Claude Code

## Prompt

> Lets make the UI more aesthetic. Use UI UX pro max skill to revamp whole UI and push to stage and main

The ui-ux-pro-max skill's design-system search (HR salary analytics dashboard) suggested a data-dense
dashboard style, a deep blue primary with an amber accent, and tabular figures. Fourteen decisions were
then asked one at a time and recorded in ADR-054, which also splits the redesign into 8.8–8.12.

## Test list (approved)

Approved as drafted, including retiring the phone-menu spec (27). Wording of 9, 19, 20 and 22 tightened
after the reviewer's pass on the failing tests. Axe findings on pages not yet
redesigned are fixed in this task (ADR-054). The engineer then asked for 8.8–8.12 in this session.

Unit specs (Vitest), `core/theme.spec.ts`:

1. `defaultsToSystemWhenNothingIsStored` — no stored choice gives the System mode.
2. `restoresTheStoredChoice` — a stored `light` or `dark` is the mode on start.
3. `treatsAnUnknownStoredValueAsSystem` — `"purple"` in storage gives System.
4. `fallsBackToSystemWhenStorageThrows` — a storage read that throws gives System, and a write that
   throws still changes the mode for this visit.
5. `cyclesSystemThenLightThenDark` — the toggle goes System → Light → Dark → System.
6. `savesEachChoice` — every change is written to storage under one key.
7. `appliesTheDarkClassForDark` — Dark puts the dark class on `<html>`; Light takes it off.
8. `followsTheOperatingSystemOnSystem` — System applies dark exactly when `prefers-color-scheme: dark`
   matches, and updates when the OS setting changes.
9. `ignoresOperatingSystemChangesOnAnExplicitChoice` — with Dark chosen on a dark OS, the OS turning light
   leaves the page dark.

Unit spec, `core/theme-preset.spec.ts`:

10. `usesIndigoForPrimary` — the preset's primary palette maps to indigo 50–950.
11. `usesSlateForSurfacesInBothModes` — light and dark surface palettes are slate.

Unit specs, `shell.spec.ts` (new tests):

12. `showsTheBrandMarkLinkingHome` — the top bar has the mark and "Salary Management", linking to `/`.
13. `labelsTheThemeToggleWithTheCurrentAndNextMode` — the toggle's accessible name is, for example,
    "Theme: System. Switch to light", and it changes after a click.
14. `showsBottomTabsWithTheSameLinksOnPhones` — a `bottom-nav` with `/`, `/catalog`, `/settings`,
    each with a visible label.
15. `marksTheCurrentSectionInTheBottomTabs` — `aria-current="page"` on the active tab only.

Unit spec, `shared/page-header.spec.ts`:

16. `rendersTheTitleAsAHeadingBelowTheAppHeading` — the title is an `h2` (the shell keeps the one `h1`).
17. `projectsPageActions` — content in the actions slot appears in the header.

Playwright, `e2e/theme.e2e.ts` (desktop and phone):

18. `rememberTheThemeAcrossAReload` — choose Dark, reload: still dark.
19. `appliesAStoredDarkThemeBeforeTheAppStarts` — with Dark stored, `<html>` has the dark class the
    moment `<body>` is parsed, before Angular boots (no white flash); so the script sits in `<head>`.
20. `followsTheEmulatedColourScheme` — with System and an emulated dark scheme, the page is dark: the
    dark page background is slate-950.
21. `usesInterWithTabularFigures` — body text resolves to Inter; amounts have `tabular-nums`.
22. `turnsTransitionsOffForReducedMotion` — the theme toggle has a transition normally; with reduced
    motion its transition duration is 0 (the global rule sets durations, not `transition: none`).

Playwright, `e2e/a11y.e2e.ts` (desktop and phone, light and dark):

23. `hasNoAxeViolationsOnInsights` — WCAG 2.1 AA rules, including colour contrast; each run first checks
    the page really is light or dark, and waits for animations to finish.
24. `hasNoAxeViolationsOnCatalog` — the same, with the drawer open on an employee.
25. `hasNoAxeViolationsOnSettings` — the same.
26. `neverScrollsSidewaysAtPhoneWidth` — at 390 px, no page is wider than the viewport.

Existing tests:

27. **Retire** `shell.spec.ts` › `opens a menu with the same links on phones`: the ☰ menu is replaced by
    bottom tabs (ADR-054). Needs the engineer's OK; replaced by 14 and 15.
    All other existing specs and E2E paths stay unchanged and must stay green; the phone E2E paths
    prove the bottom tabs never cover the drawer's buttons.

## Notes

- The committed `test:` (`52ce516`) had literal backspace bytes where `` was meant in the axe
  helper's regex (an AI scripting slip), so the light check could never fail and the dark one never
  pass. Restored to `/app-dark/` in its own `fix:` commit; the reviewer confirmed the bytes.
- Implementation review: reading `window.localStorage` itself throws with blocked site data, which would
  have left the app blank; the storage factory now falls back to memory (its test is 8.9's item 9).
  Unused icons and an accent token that missed 4.5:1 were removed; the active pill got a dark-mode fill.
- For 8.10–8.12: the page header's blur makes it a containing block, so an overlay placed in its actions
  slot needs `appendTo="body"`.

## Outcome

Indigo and slate preset, Inter, app colour tokens for both modes, a System/Light/Dark toggle with no
flash on load, refined top bar, bottom tabs on phones, page header. 154 unit tests and 27 Playwright
checks (axe in light and dark at desktop and phone) green.
