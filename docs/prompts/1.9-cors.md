## Outcome

One `cors.allowed-origins` value feeding both CORS surfaces, defaulting to the Angular
dev server so `ng serve` works with no `.env` at all.

**The decision existed because Claude found something while planning the slice:** Spring
keeps two unrelated CORS configurations — actuator endpoints are configured by
properties, MVC endpoints by a `WebMvcConfigurer` — and setting one does nothing for the
other. The actuator half is what the health page needs, since the browser calls
`/actuator/health` directly; `CorsConfig` covers MVC so phase 3's first controller is
reachable without anyone rediscovering why it is not.

This slice ran the TDD loop properly, unlike 1.3: two of three tests genuinely failed
first, then passed.

Two things recorded honestly in the commits rather than smoothed over:

- The third test, "unknown origin is refused", **passed vacuously** before
  implementation, because with no CORS configured nothing gets a header. It only becomes
  meaningful paired with the first test, where together they prove the allowlist
  discriminates rather than echoing every origin back.
- The MVC surface ships with no test of its own, because no endpoint exists to exercise
  it. Contriving a test-only controller would change Spring's context-cache key and start
  a second Postgres container for the run. Covered by the first controller slice test in
  phase 3.
