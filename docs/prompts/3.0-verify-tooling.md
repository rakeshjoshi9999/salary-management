## Approved checks (acceptance criteria)

Tooling, not JUnit tests. Failure cases are proven locally with a throwaway file, then removed; CI is
not shown going red.

1. `checkoutIsLf` — after `.gitattributes` and a re-checkout, working-copy text files are LF.
2. `mvnwCmdStillRuns` — `mvnw.cmd` stays CRLF and `mvnw.cmd -v` runs.
3. `formatCheckPassesOnRepo` — `npm run format:check` passes after the reformat.
4. `formatCheckFailsOnUnformattedFile` — a badly formatted `.ts` file fails it.
5. `lintPassesOnCurrentCode` — `npx ng lint` passes on the existing app.
6. `lintFailsOnAccessibilityViolation` — `<img>` without `alt`, or a keyboard-less `(click)` on a
   `<div>`, fails lint.
7. `lintFailsWithoutOnPush` — a component without `OnPush` fails lint.
8. `lintFailsOnNonSignalState` — a decorator `@Input()` where a signal input fits fails lint.
9. `backendCoverageReportGenerated` — `mvnw test` writes JaCoCo HTML, XML and CSV; tests stay green.
10. `backendCoverageIncludesTestcontainersTests` — code run only by the Testcontainers smoke test shows
    as covered.
11. `frontendCoverageReportGenerated` — `ng test --watch=false --coverage` writes HTML; tests stay green.
12. `buildsStillGreen` — `ng build` and the `stage` build succeed.
13. `ciRunGreenWithThreeJobs` — on the stage push, backend, frontend and frontend-lint pass; both
    coverage reports are uploaded.
14. `ciSummaryShowsCoverage` — the run summary shows line and branch % for both tiers.
