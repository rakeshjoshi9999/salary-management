## Approved test list (acceptance criteria) — phase 7

### 7.1 Core: API models, error handling, services, the money pipe, the shell
**Error interceptor**
1. turns a Problem Details response into an `ApiError` with its `code` and `status`
2. maps `VALIDATION_FAILED` errors into field errors, keyed by field name
3. carries `currentVersion` for `STALE_VERSION`
4. carries `errorId` for `INTERNAL_ERROR`
5. turns a request that got no response into `NETWORK_ERROR`
6. gives a non-Problem error body a code by its status family (a Render 502 page becomes `INTERNAL_ERROR`; a 4xx becomes `MALFORMED_REQUEST`)
7. fails a request with `TIMEOUT` after 90 s with no answer (fake timers)

**Cold-start detection**

8. marks the server as waking once a request has been pending for 3 s
9. does not mark it waking for a response under 3 s
10. clears waking once every slow request has finished, whether it succeeded or failed

**Services** (`HttpTestingController`)

11. `EmployeeService.list` sends only the parameters it was given, with a 0-based page
12. `EmployeeService.get` requests `/employees/{id}`
13. `EmployeeService.create` posts the fields with no `id` or `currency`
14. `EmployeeService.update` puts the fields together with `version`
15. `EmployeeService.delete` sends a DELETE
16. `InsightsService` requests `/insights/countries/{code}`
17. `SettingsService` gets the settings, and puts `defaultCountryCode` with `version`

**ReferenceStore**

18. loads the reference data once and reports ready; a second consumer does not refetch it
19. reports an error, and Retry fetches again
20. gives a department's titles, or every title when no department is chosen
21. gives a country's currency and name

**Money pipe**

22. formats with the ISO code and en-US grouping: `INR 2,400,000.00`
23. always shows 2 decimals: `52000` becomes `EUR 52,000.00`; `0.5` becomes `0.50`
24. renders nothing for null

**Shell**

25. serves the health page at `/health`
26. shows Insights, Catalog and Settings links in the top bar
27. marks the current section as active
28. opens a ☰ menu with the same links on phones
29. shows the cold-start banner while the server is waking
30. shows an app-level reference error with a Retry that recovers

### 7.2 Catalog
**Reading the URL** (a pure function)
1. uses the defaults for an empty query: page 0, size 20, `fullName,asc`
2. keeps valid search, filters, sort, page and size
3. drops a country, department or title that isn't in the reference data, and reports it as ignored
4. turns a size other than 20, 50 or 100 into 20, and reports it
5. drops an unsupported sort, and reports it
6. drops a one-character `q`, and reports it
7. turns a negative or non-numeric page into 0, and reports it
8. ignores unknown parameters, and reports them
9. writes a query back out without its defaults

**Catalog page**

10. requests employees using the query from the URL
11. shows each row's name and email, title, department, country, salary and hire date
12. shows the same employees as cards in the phone layout
13. shows the range and total: "1–20 of 10,000"
14. waits 300 ms after typing before searching
15. doesn't search on 1 character, and shows "Type at least 2 characters"
16. searching goes back to page 0 and replaces the URL instead of adding to history
17. changing a filter navigates and goes back to page 0
18. picking a department narrows the title options; clearing it restores them all
19. picking a department clears a selected title that isn't in it
20. clicking a sortable header toggles asc/desc; other headers don't sort
21. changing the page navigates with a 0-based page
22. changing the page size goes back to page 0
23. invalid values in the link are replaced in the URL, with one toast
24. a page past the end goes to the last page
25. a newer query cancels the response still pending from the previous one
26. shows skeleton rows on first load, and dims the existing rows while the next page loads
27. an empty catalog shows "No employees yet" with Add
28. no matches shows "No one matches these filters"; Clear filters goes to `/catalog`
29. an error shows "Couldn't load employees"; Retry fetches again
30. clicking a row opens `/catalog/:id` and keeps the list's query
31. Add employee opens `/catalog/new` and keeps the query
32. the phone filter button shows the number of active filters: "Filters (2)"
33. the phone Sort dropdown navigates with the chosen sort

### 7.3 Employee drawer: view, add, edit
**View**
1. loads the employee by id and shows name, email, title, department · country, salary and hire date
2. a 404 shows "This employee no longer exists" with Close
3. Close returns to the Catalog with the list's query kept

**Form**

4. the add form at `/catalog/new` starts empty
5. the edit form is filled in from the employee
6. every field is required
7. rejects an invalid email, including one with no dot in its domain, such as `a@b` (ADR-037)
8. rejects a salary of 0 or less
9. rejects a salary with more than 2 decimals
10. rejects a hire date before 1950-01-01 or after today in UTC (today from an injected clock); the date picker disables those dates
11. enforces the length limits: name 200, email 254
12. the title is disabled until a department is picked, then lists only that department's titles
13. changing the department clears the title
14. the currency label follows the selected country
15. Save on add posts the trimmed values and opens the new employee at `/catalog/:id`
16. Save on edit puts the values with `version`, switches to view mode with a "Saved" toast, and refreshes the list row
17. while saving, the inputs are locked and Save shows a spinner
18. `VALIDATION_FAILED` errors show on the matching fields
19. `DUPLICATE_EMAIL` shows on the email field
20. `STALE_VERSION` shows the banner, keeps the edits and disables Save
21. Reload latest refetches the employee and reopens the form on the fresh data
22. any other error shows a toast and keeps the edits
23. a 404 on save shows "This employee no longer exists"
24. leaving a changed form asks "Discard changes?"; leaving an unchanged one doesn't
25. "Keep editing" cancels the navigation
26. after a successful save, closing the drawer doesn't prompt

### 7.4 Delete
1. Delete opens a confirm dialog that names the employee
2. Cancel keeps the drawer open and sends nothing
3. confirming deletes the employee, closes the drawer, shows a "Deleted" toast and reloads the list on the same page
4. deleting the last row on a page reloads the previous page
5. an employee already deleted (404) shows a toast and reloads the list
6. any other error shows a toast and keeps the drawer open

### 7.5 Insights dashboard
1. `/` shows the Insights dashboard; `/health` still shows the health page
2. a country in the URL is used without asking for the settings
3. with no country in the URL, the saved default country is used
4. if loading the settings fails, India is used
5. shows five cards: headcount (`3,500`), median, average, min and max, the salaries in the country's currency
6. average-by-title rows keep the API's order, with each bar's width scaled to the highest average
7. each title row shows its department and headcount
8. the doughnut gets the departments in the API's order
9. the legend shows each department's count and percentage
10. the doughnut's centre shows the total headcount
11. choosing another country changes `?country=` only, and doesn't save the default
12. a headcount of 0 shows "No employees in {country} yet" with a link to the Catalog
13. an unsupported country (404) falls back to the default country, with a toast
14. shows skeleton cards and bars while loading
15. an error shows "Couldn't load insights" with Retry
16. the chart code isn't in the initial bundle (checked through the lazy route)

### 7.6 Loading, empty and error states everywhere
1. the shared state panel shows a loading skeleton, an empty message with an optional action, or an error with Retry
2. the cold-start banner says "Waking the server… this can take up to a minute"
3. a Catalog `TIMEOUT` shows the error state with Retry
4. filters and form dropdowns stay disabled until the reference data is ready
5. the drawer's view shows a skeleton while loading
6. a `NETWORK_ERROR` on any page shows that page's error state, not a blank page

## Outcome

All eight slices built test-first, each reviewed at the test step and the code step (at most two rounds),
committed as `test:` then `feat:`, and pushed to `stage`. 137 unit and component tests, plus 4 Playwright
runs (2 paths × desktop and phone) that passed locally against the real stack.

What the reviewer caught, and how it was resolved (selected):
- **Tests that a wrong implementation would pass:** the cold-start counter never mixed fast and slow
  requests; the debounce check spied on one router method; a country fixture whose order was also
  alphabetical; a department fixture that could not tell API order from a client sort; a stale-settings
  test that reloaded a country absent from the fixture, so it could never pass. All fixed before `test:`.
- **Conflicts with the design docs:** a page past the end skipped the toast UI_DESIGN and ADR-051 ask for;
  the code now follows the docs.
- **Bugs in the implementation:** a double toast for a link with two bad values; the add form could submit
  empty department, country and title while reference data loaded (disabled controls skip validation);
  the edit form's title cleared itself when the employee arrived before the reference data; closing the
  drawer mid-delete dropped the result; a stale "refresh" flag could hide a real warning (now carried
  through the stream as the load's reason); doughnut colours below 3:1 contrast.
- **Found by screenshots, not tests:** no icon rendered anywhere, because PrimeIcons was never installed
  (the phase 1 health page had the same gap). Icons are now inline SVG in `shared/icon.ts`, with no new
  dependency.

Judgement calls made inside the slices (open to change): native `<select>` and `<input type="date">`
instead of PrimeNG inputs (accessible, testable, the browser enforces min/max dates); duplicate email is
a field error; saving an add also refreshes the list and says "Saved"; a delete that empties a page
steps back without the "part of the link" warning.

Open for the engineer: the initial bundle is about 697 kB against the 500 kB warning budget (1 MB error),
up from 606 kB at the start of the phase (PrimeNG Drawer, Toast, ConfirmDialog in the shell). Chart.js
and the table load lazily with their routes.
