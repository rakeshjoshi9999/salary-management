## Outcome

`POST /api/v1/employees` landed; backend suite 109 tests green (66 new cases from the 41 approved tests,
43 existing), JaCoCo 96%. Commits: `refactor:` CorsConfig move, `test:`, `feat:`, `docs:`.

Reviewer, tests step: round 1 found 2 should-fix (a `Set` hid a second error on the same field; the
salary-format test passed on a value that already had 2 decimals) and 2 nits, all fixed except one nit
kept on purpose: `ReferenceServiceTest` still checks `isDepartment`, the only test of departments loaded
from the database. `readsSalaryExactly` uses `isEqualTo`, not `isEqualByComparingTo`, on purpose: the
scale must survive too, which proves no `double` step. Round 2: PASS.

Reviewer, implementation step: PASS with 3 nits. Fixed: an over-long title or department no longer gets
a second "unsupported" error, and the country-code pattern is one constant. Left for 3.7: the handler
maps only field errors, so a future object-level constraint would be dropped.

Found during implementation: Hibernate Validator's `@Digits` counts trailing zeros and rejects `100.000`,
against what the AI had said when offering decision 8. A small `@MoneyAmount` constraint replaces it;
ADR-037 records the correction. `@Email` with a `regexp` also matched the empty string against the
pattern, so the pattern accepts empty and `@NotBlank` alone reports blanks.
