# 8.13 — Long cards scroll inside themselves; no page scroll behind the drawer

**Task:** `TASKS.md` 8.13 · **Date:** 2026-11-13 · **Tool:** Claude Code

## Prompt

> Then heights of the cards are going beyond the screen. I want the height of the catalogue table,
> Average salary by job title to be max to the screen height and then add scroll inside the card if it
> overflows. I can scroll the catalogue even if the Add employee sidebar is open. Fix these issues

Two decisions were asked one at a time and recorded in ADR-056, which supersedes ADR-055: tablet and
desktop only; in the Catalog card only the rows scroll. The job-title card's layout was the AI's stated
default.

## Test list

Playwright, `e2e/card-scroll.e2e.ts`:

1. `fitsTheCatalogCardToTheScreen` (desktop, 100 rows per page) — the card ends inside the viewport and
   its rows scroll inside it.
2. `keepsTheToolbarHeaderAndPagerInViewWhileRowsScroll` (desktop) — after scrolling the rows to the end,
   the search box, the column header and the paginator are still visible inside the card.
3. `fitsTheJobTitleCardToTheScreen` (desktop) — the card is no taller than the viewport, its title stays
   put and its table scrolls.
3a. `fitsTheCatalogCardToTheScreenOnATablet` (768 x 1024) — ADR-056 says from 640 px, so a tablet width
   caps too. Added after the test review; it enforces the decision, it adds no behaviour.
4. `keepsNormalPageScrollingOnPhones` (phone) — the Catalog card is not capped: it is taller than the
   screen and the page scrolls.
5. `holdsThePageAndTheListStillBehindTheOpenDrawer` (phone and desktop) — with the drawer open the body
   is locked (`overflow: hidden`), and a mouse wheel over the list moves neither the page nor, on
   desktop, the rows. The lock is asserted directly, because the capped desktop page has nothing to
   scroll.

Existing tests stay unchanged; the axe checks cover the scrolling Catalog and Insights in both themes.
